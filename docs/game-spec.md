# FPS要素仕様（gakushu-fps）

学習バトルフィールドにおける「FPS風訓練ゲーム」の要素仕様案。README記載の基本方針・学習サイクルを前提とし、それをPUBGモバイル/APEX Legendsに近い本格的なFPS体験（照準・索敵・立ち回り・進級）に落とし込む。

> **2026-07-17改訂**: 当初は人体・実在武器を模さない抽象表現（幾何パネル・スキャン演出）を安全設計上の前提としていたが、保護者（プロジェクトオーナー）の判断により撤回。対象の子どもたちは日常的にPUBGモバイルをプレイしており、同水準の表現は許容する。以降は「見た目・戦闘感をPUBG/APEX相当に近づける」ことを優先する。

## 前提（保護者の判断による現行の安全設計）

- 対戦相手はPUBG/APEX風のAI兵士（人型）でよい。武器も実在の銃器を模したモデル（ライフル・ハンドガン等のシルエット）でよい。銃撃・命中・撃破（膝崩れ落ち等の簡易モーションで消える）といった一般的なタクティカルシューター表現を用いる。
- 除外する表現（PUBGモバイル自体にも通常含まれない範囲）：流血・グロテスク表現、身体欠損描写、実在の人物・団体を模した敵、差別的・ヘイト的表現、性的表現。演出は「PUBGモバイル程度」を上限の目安とする。
- **対人マルチプレイ（見知らぬ他者とのオンライン対戦）は現時点では行わない。** これは表現の過激さの問題ではなく、年少者がオンラインで不特定多数と接触するリスク（チャット・音声トラブル、モデレーション不能）を避けるための制約であり、引き続き有効。対戦相手はすべてローカルのAIボット（NPC）とする。将来的に家族・知人限定の小規模マルチプレイを検討する余地はあるが、実装する場合は別途モデレーション・保護者管理機能の設計が必要。
- 学習サイクル：読む → 要点を拾う → 解き方を選ぶ → 答える → 手順を再現する。この教育的骨格は表現の変更に関わらず維持する。

## 想定デバイスと性能方針

想定デバイスは低スペックAndroidスマホとChromebook（ハイエンド端末・ゲーミングPCは非対象）。ブラウザ上のBabylon.js(WebGL)で3D一人称視点シューティング風の体験を破綻なく動かすため、下記の方針を採る。

- **自由移動は採用しない。ウェイポイント間のレール移動＋視点操作のみ自由**とする（物理演算・ナビメッシュ不要）。
- 目安値：総ポリゴン数5万以下、ドローコール30以下、テクスチャは512px以下のアトラス1〜2枚。
- `engine.setHardwareScalingLevel(1.5〜2)` で内部解像度を下げる、`scene.freezeActiveMeshes()`、マテリアルの`freeze()`を使う。
- リアルタイムシャドウは禁止し、ブロブ影テクスチャで代替する。ポストプロセスは使用しない。ライトは環境光＋1灯のみ。
- 妨害ドローンなどの動くオブジェクトはthin instances＋ビルボードで描画する。
- フレームレートは60fpsを狙わず30fps固定とし、描画負荷ではなく入力遅延の最小化を優先する。
- 初回起動時に3秒程度の簡易ベンチマークを行い、Chromebook/AndroidのANGLE実装差を吸収する形で描画品質を自動段階切替する。

3D負荷が高くなりがちな「自由移動＋高頻度の敵AI移動」は採用せず、後述の通り3D区間を照準訓練に限定し、移動・索敵判断は2Dフェーズに分離することで、低スペック環境でも照準体験の質を落とさない設計とする。

敵AI兵士モデル・銃器ビューモデルを導入する場合も、上記の目安値（総ポリゴン数5万以下・ドローコール30以下）を厳守すること。人型敵は低ポリ（1体あたり数百〜千ポリゴン程度目安）、ビューモデルの銃も簡略形状とし、テクスチャは共有アトラスで賄う。動く敵AI兵士は引き続きthin instances等での描画を優先し、個別メッシュの乱立を避ける。

## PUBGモバイルからの技能転移要素

PUBGモバイル/APEX的な「上手さ」（エイム・判断力・空間認識・反応速度・立ち回り）を、見た目・操作感ともに近い形で各学習フェーズに組み込む。

| PUBGモバイルの技能 | 学習ゲームへの落とし込み |
|---|---|
| エイム（追い偵・フリック） | 誤答役の敵AI兵士を等速→加速→ジグザグの3段階で動かし、リード照準を要求。照準は自動ロックではなく、明示的な発射操作（発射ボタン/クリック/スペースキー）で撃つ方式とし、狙って撃つ判断を要求する |
| 索敵・音の聞き分け | 正解の敵AI兵士がいる方角をステレオ信号音で提示。ミニマップには音源の方位のみを表示し、姿は見せない |
| ポジショニング・立ち回り | 補給箱（ヒント）を遮蔽物の裏に配置。ウェーブ間に、制限時間内に安全ルートを選ぶ「移動フェーズ」を挿入し、縮小していく「学習ゾーン」でエリア管理を再現 |
| 着地取り | ミッション開始時に俯瞰マップから挑戦エリア（降下地点）を選択し、難度と報酬のトレードオフを判断させる |
| リコイル制御 | 連射中は照準が上方向に流れる本格的なリコイルパターンを実装し、引き戻し操作を要求する。手順再現ボス戦の入力方式にも統合する |
| 統計 | 命中率（正答率）に加えて「先制発見率」「エリア内滞在率」を学習ログの指標に追加する |
| 武器・命中演出 | 一人称視点の銃器ビューモデル、マズルフラッシュ、着弾エフェクト、ヒットマーカー、撃破モーションなど一般的なタクティカルシューターの演出を用いる |

## ミッションのフェーズ構成

学習サイクルと技能転移要素、および描画負荷のバランスを踏まえ、ミッションを次の5フェーズに分割する。3Dレンダリングは交戦・再現ボス戦のみに限定し、それ以外は2D俯瞰表示で負荷をかけない。

| フェーズ | 内容 | 描画負荷 | 対応する学習/PUBG要素 |
|---|---|---|---|
| ① 降下選択（2D俯瞰） | マップから挑戦エリアを選択し、リスクと報酬を提示する | 極小 | 着地取り、リスク判断 |
| ② 索敵（2D俯瞰＋方位音） | 課題文を読み要点を拾う。正解の方向を音で把握する | 極小 | 索敵・音の聞き分け、読解 |
| ③ 交戦（3Dレール視点） | 敵AI兵士（誤答）を避けつつ、正解の敵AI兵士を狙って撃破する | 中（前述の最適化を適用） | エイム・トラッキング、解法選択 |
| ④ 再現ボス戦（3D/2D切替可） | リコイル制御を模した連続入力で、解法・手順を正しい順序で再現する | 中〜低 | 手順の再現性、リコイル制御 |
| ⑤ デブリーフ | 命中率・先制発見率・エリア内滞在率などのログを表示する | なし | 学習記録（正答率・弱点・再現性） |

## その他のFPS要素

- **HUD**：クロスヘア（照準の状態を色で可視化）、残弾数（無制限連射は不可とし、考えてから撃つ設計を誘導）、制限時間ゲージ、ミニマップ（フェーズ②の音源方位表示を含む）
- **コンボ／連続正解**：連続正解で「作戦ランクアップ」「武器強化」などの視覚・効果音フィードバックを与える
- **作戦カード（ロードアウト）**：ミッション開始前に「国語偵察」「算数工兵」「英語通信」など科目別クラスを選択する
- **補給箱＝ヒントシステム**：一定条件で開放され、部首・公式・単語のヒントを提供する。多用は評価に影響させ、自力での再現性を優先させる
- **ランク／進級システム**：「訓練生→隊員→…」といった階級演出で、学年別・科目別に独立した習熟度を可視化する

## ロードマップ段階との対応

| README記載のロードマップ | 対応するFPS要素 |
|---|---|
| 1: プロフィール選択、科目・学年別ミッション、進捗保存 | 作戦カード（クラス選択）、降下選択フェーズ |
| 2: 3D訓練場、回答ターゲット、作戦カード、連続正解・再挑戦 | 交戦フェーズ、HUD、コンボ、敵AI兵士 |
| 3: 文章読解の段階表示、解法再現チェック、漢字の想起学習 | 索敵フェーズ、再現ボス戦、補給箱ヒント |
| 4: 保護者向け弱点レポート、教材追加、学習履歴の分析 | 命中率・先制発見率・エリア内滞在率などのログ計測 |
